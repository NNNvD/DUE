# Repository Guidelines

## Project Structure & Module Organization
- Source: `site/` (11ty input). Layouts in `site/_includes/`, data in `site/_data/`, assets in `site/assets/`.
- Content: Markdown essays under `site/essays/`.
  - Drafts: `site/essays/drafts/*.md`
  - Published: `site/essays/published/*.md`
- Automation scripts: `scripts/*.js` (`autopublish`, `checkWordRange`, version bump/credit).
- Build output: `_site/` (generated by Eleventy).

## Build, Test, and Development Commands
- `npm run start`: Run Eleventy dev server with live reload at `http://localhost:8080`.
- `npm run build`: Build static site into `_site/`.
- `npm run check:words`: Validate essay word counts using front‑matter `word_range`.
- `npm run autopublish`: Move overdue drafts to published and set version/date.

## Coding Style & Naming Conventions
- JS: Prefer 2‑space indentation; keep functions small and pure in `scripts/`.
- Templates: Nunjucks (`.njk`) in `site/_includes/`; keep presentation logic in templates, data/filters in config.
- Slugs: Lower‑kebab‑case filenames for essays (e.g., `on-deadlines-and-honesty.md`).
- Front matter: Use the provided keys (`title, keywords, author, status, started_at, deadline_at, initial_status, version, published_at, word_range, release_notes`). `topic` is still accepted as a legacy fallback for older essays.

## Testing Guidelines
- No unit test framework is configured. Use:
  - `npm run build` to catch template/front‑matter errors.
  - `npm run check:words` to enforce word ranges.
- Keep PRs small and focused; include sample render links or screenshots when changing layouts/styles.

## Commit & Pull Request Guidelines
- Commits: Clear, imperative subject lines (e.g., "Add word-range check for drafts").
- PRs: Link issue (if any), describe scope and rationale, and label intent:
  - `minor`: small edits → patch bump, added to Acknowledgments.
  - `major`: substantial edits → major bump, added to Coauthors.
- Content changes: reference file paths (e.g., `site/essays/drafts/<slug>.md`) and note front‑matter edits.

## Security & Configuration Tips
- Pages deploys via Eleventy; do not commit `_site/`.
- Dates must be ISO (`YYYY-MM-DD`) for filters and scripts.
- Update `site/_data/site.json` for title, baseUrl, and repo URL.
