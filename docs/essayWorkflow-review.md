# Review of `essayWorkflow.md`

## Summary of the proposed workflow
- Add a Decap CMS admin UI under `/admin/` with `admin/index.html` and `admin/config.yml`, storing essays in `content/essays/` with Decap's editorial workflow enabled.【F:essayWorkflow.md†L89-L246】
- Standardize essay front matter on `title`, `date`, `author`, `topic`, `keywords`, `length_category`, `version`, `status`, and optional `word_count`, with filenames generated via a Decap slug template.【F:essayWorkflow.md†L53-L224】
- Recommend Netlify Identity/Git Gateway or an external OAuth service for authentication, depending on whether hosting stays on GitHub Pages.【F:essayWorkflow.md†L256-L299】
- Outline follow-up steps: wire the static site generator to read `content/essays/`, map `length_category` to visual cues, and document the admin flow in the README.【F:essayWorkflow.md†L302-L498】

## Potential conflicts with the current architecture
1. **Content location and build pipeline mismatch**: The plan expects essays under `content/essays/` and relies on Decap's folder structure, but the site currently renders Markdown from `site/essays/` (drafts/published) and ships Eleventy data/templates around that path.【F:essayWorkflow.md†L242-L253】【F:README.md†L7-L23】【F:site/essays/essays.11tydata.js†L1-L74】 Moving files without updating the Eleventy pipeline would break rendering.
2. **Front matter schema drift**: The proposed schema omits required DUE metadata such as `coauthors`, `acknowledgments`, `started_at`, `deadline_at`, `initial_status`, `release_notes`, and `word_range`, and uses different status and version semantics (e.g., `draft/under_review/published` vs. current `proposed/draft/published` and semantic versions like `0.1.0`).【F:essayWorkflow.md†L53-L224】【F:README.md†L37-L69】【F:site/essays/drafts/on-deadlines-and-honesty.md†L1-L33】 Adopting the new schema as-is would break the automation that enforces deadlines, word ranges, and release notes.
3. **Workflow and automation alignment**: The plan leans on Decap's editorial workflow, but the repo already includes CLI scaffolding (`npm run new`), scheduled/manual autopublish, word-range checks, and release-note/version guards tied to the existing front matter and folder layout.【F:essayWorkflow.md†L145-L238】【F:README.md†L9-L72】 Introducing Decap without adapting these scripts could cause failing CI or bypass required publishing controls.
4. **Hosting expectations**: The repo is designed for GitHub Pages + Actions, while the recommended path in the workflow shifts toward Netlify Identity/Git Gateway or an external OAuth backend. That introduces operational work beyond the current Pages setup and needs an explicit choice to avoid blocking `/admin/` logins.【F:essayWorkflow.md†L256-L299】【F:README.md†L2-L15】
5. **Media handling**: The plan configures uploads under `static/uploads` and `/uploads`, but the current Eleventy assets live under `site/assets/`; without asset pipeline changes, uploaded media would not be served by the site build.【F:essayWorkflow.md†L128-L198】【F:README.md†L7-L23】

## Recommended adjustments for a smoother path forward
- **Keep the current content root and schema as the source of truth**: Configure Decap (if adopted) to read/write `site/essays/drafts/` and `site/essays/published/` instead of `content/essays/`, and mirror the existing front matter fields (including `coauthors`, `acknowledgments`, `deadline_at`, `initial_status`, `release_notes`, and `word_range`). This preserves automation and template compatibility.【F:README.md†L7-L69】【F:site/essays/drafts/on-deadlines-and-honesty.md†L1-L33】
- **Map Decap widgets to current validation rules**: Use list/regex limits that reflect the `topic` and `keywords` constraints already enforced by Eleventy data transforms, and keep the `word_range` buckets (250–500, 500–1000, 1000–1500) so existing word checks stay valid.【F:essayWorkflow.md†L168-L219】【F:README.md†L9-L55】
- **Integrate with existing workflows**: Update Decap `publish_mode` and status options to align with `proposed`/`draft`/`published`, ensure `npm run new` output matches the CMS schema, and adjust autopublish scripts only after the schema is harmonized to avoid CI regressions.【F:essayWorkflow.md†L145-L238】【F:README.md†L9-L72】
- **Clarify hosting strategy before implementation**: Decide whether to remain on GitHub Pages (requiring an external OAuth backend for Decap) or move to Netlify + Git Gateway; document the choice in `README.md` alongside any new admin endpoints to keep onboarding clear.【F:essayWorkflow.md†L256-L299】【F:README.md†L2-L23】
- **Plan asset delivery**: If Decap uploads are needed, extend the Eleventy build to copy `static/uploads` (or another chosen folder) into the published assets so CMS media resolve on the live site.【F:essayWorkflow.md†L128-L198】【F:README.md†L7-L23】
